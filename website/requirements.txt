# What the site depends on, as a human writes it. What it *installs* is
# requirements.lock, which pins every transitive package to an exact version and a
# hash. The Dockerfile and CI both use the lock, so a rebuild resolves the same set
# every time and pip-audit reports on what is actually deployed rather than on
# whatever pip picked that morning.
#
# Change a dependency here, then regenerate both locks:
#
#     uv pip compile requirements.txt     --universal --python-version 3.12 \
#         --generate-hashes --no-strip-extras -o requirements.lock
#     uv pip compile requirements-dev.in  --universal --python-version 3.12 \
#         --generate-hashes --no-strip-extras -o requirements-dev.lock
#
# 3.12 because that is what the image runs. --universal because the image is Linux while
# people develop on Windows: without it the lock is resolved for whichever platform
# compiled it, and uvicorn[standard] quietly loses uvloop when that is Windows — which
# then fails `pip install --require-hashes` inside the image, with nothing in the lock to
# suggest why. One lock, with environment markers, that installs correctly on both.
